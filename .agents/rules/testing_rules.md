# ユニットテスト & 入力バリデーション作成における必須ルール

今後このプロジェクト（`pmFit`）でユニットテストを作成・追加する際は、すべての数値入力やフォーム判定処理において、以下の3つの観点を**必ず毎回漏れなくテストケースおよび実装に盛り込んでください**。

---

## 1. 文字列・型違い・不正入力のテスト
- 文字列入力（例: `"abc"`, `"invalid"`, `""`, `"  "`）
- `NaN`, `null`, `undefined` などの想定外のデータ型
- 正常な数値形式の文字列（例: `"65.5"`）の安全なパース検証

## 2. 厳密な境界値分析 (Boundary Value Analysis: BVA)
- **最小境界値 (Min Boundary)**:
  - 最小値そのもの (On-point, 許可)
  - 最小値よりわずかに小さい値 (Off-point: e.g. `MIN - 0.01`, 拒否)
- **最大境界値 (Max Boundary)**:
  - 最大値そのもの (On-point, 許可)
  - 最大値よりわずかに大きい値 (Off-point: e.g. `MAX + 0.01`, 拒否)

## 3. 過剰値・数値オーバーフロー対策 (Extreme & Overflow Testing)
- **巨大数値・オーバーフロー**:
  - `Number.MAX_SAFE_INTEGER` (9,007,199,254,740,991)
  - `Number.MAX_VALUE` (1.79e308)
  - 指数表記の巨大文字列 (e.g. `"1e20"`, `"9999999999999999999"`)
- **特殊数値**:
  - `Infinity`
  - `-Infinity`
  - `Number.MIN_SAFE_INTEGER` などの負の極端値
- 実装側で `Number.isFinite()` による安全評価を必ず行うこと。
